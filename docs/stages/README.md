## 5. 跨阶段核心原则

1. **可观测先行**：任何新功能上线必须有指标、链路、日志，否则视为不合格。
2. **配置外部化**：所有凭据走 `config/settings.py` + `.env` + K8s Secret；代码不写死任何 endpoint、key、URL。
3. **缺依赖可降级**：与 5b 设计一致（mock 兜底 + warning），生产环境只允许在指标上看到 "degraded=true" 而不阻断业务。
4. **灰度与回滚**：5d 起的所有部署必须支持按租户 / 区域 / 流量的灰度策略，并保留 ≤ 5 分钟回滚窗口。
5. **数据可追溯**：审查报告 / 违规项 / 法规版本全部存证，与 4d 报告链路一致；客户可调阅。
6. **客户零感知降级**：短信 / 钉钉 / 企微 / IFC / InfluxDB 任一真实渠道失败时，业务主流程不得报错。

## 6. 度量与 SLA 目标

| 指标           | 目标值        | 测量方式                                              |
| ------------ | ---------- | ------------------------------------------------- |
| API P95 响应时间 | ≤ 800ms    | Prometheus `http_request_duration_seconds_bucket` |
| API 错误率（5xx） | ≤ 0.5%     | Prometheus `http_requests_total{status=~"5.."}`   |
| 智能体任务成功率     | ≥ 99%      | 编排层事件总线 + 业务埋点                                    |
| 通知到达率        | ≥ 99.5%    | 通知渠道层埋点 + 客户回执                                    |
| 报告生成 SLA     | 单份 ≤ 90s   | 编排层任务时间戳差                                         |
| 可用性          | ≥ 99.9%（月） | 健康检查 + 业务可用性合成                                    |
