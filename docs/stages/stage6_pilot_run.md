# 阶段 6 · 试运行

> 版本：2026-09-03
> 周期：3 周（15 工作日）
> 前置：5e 质量保障完成
> 后置：7 正式上线

## 1. 目标

用真实业务流量验证整套系统，从"我们自己用得好"到"客户用得好"。三段渐进：**内测**（团队自验）→ **试点**（1 个真实项目合作）→ **公测**（3-5 个项目小范围接入）。每段都有明确的"放行 / 暂停 / 回退"条件。

## 2. 关键交付物

### 2.1 内测（D1-D4，4 工作日）

- 测试账号矩阵：5 个角色 × 3 个虚拟租户 = 15 个测试账号
- 内测剧本：20 个核心流程（覆盖 3 个智能体 + 编排 + 通知 + 报告）
- 缺陷记录：`docs/pilot/internal_bugs.md`
- 优化清单：`docs/pilot/internal_optimizations.md`（按优先级 P0/P1/P2）
- 内测总结会签：产品 + 架构 + 测试 + SRE

### 2.2 试点（D5-D11，7 工作日）

- 试点客户对接：1 个真实工程项目（建议挑选规模中等、数据可脱敏的客户）
- 合同 / NDA / 数据使用协议
- 客户接入清单：
  - 账号开通（租户隔离）
  - 角色分配（监理 / 项目经理 / 安全员 / 商务）
  - 法规库定制（加载客户项目所在地的法规版本）
  - BIM / IFC 模型导入（如有）
  - IoT 设备接入（如有）
  - 通知渠道配置（钉钉 / 企微 webhook）
- 客户培训：3 次（操作培训 / 报告解读 / 应急流程）
- 试点日报：每日 17:00 输出，包含 4 个核心指标
- 客户反馈收集表
- 试点报告（2 周）：含系统表现 / 客户满意度 / 改进项
- 客户签字确认书

### 2.3 公测（D12-D15，4 工作日）

- 扩展到 3-5 个项目（不同规模 / 不同地域 / 不同业务类型）
- 公测准入：内测 + 试点全部 P0 修复 + 客户满意度 ≥ 4/5
- 公测监控：每项目独立 dashboard，错误率 > 1% 自动告警
- 公测日报
- 公测报告：含 3-5 客户横向对比 / 业务模式分析 / 商业化建议

| 维度 | 标准 |
| --- | --- |

| 流程 | 20 个内测流程 100% 可走通 |
| 性能 | P95 ≤ 800ms（生产规格） |
| 体验 | 团队 5 人 ≥ 4/5 满意度 |

### 4.2 试点

| 维度 | 标准 |
| --- | --- |
| 数据 | 真实业务数据 ≥ 100 份审查报告 / 50 个 IoT 告警 / 20 次 GIS 围栏越界 |
| SLA | 7 天内 SLA 4 指标全部达标 |
| 客户 | 签字确认 + NPS ≥ 40 |
| 修复 | P0 修复 ≤ 24h，P1 修复 ≤ 1 周 |

### 4.3 公测

| 维度 | 标准 |
| --- | --- |
| 客户 | 3-5 个项目稳定运行 ≥ 1 周 |
| 横向 | 不同规模 / 地域 / 业务对比表 + 改进建议 |
| 商业 | 客单价 / 续约意愿 / 口碑转介率初估 |

## 5. 风险与回退

| 风险 | 概率 | 影响 | 缓解 / 回退 |
| --- | --- | --- | --- |
| 内测 P0 缺陷堆积 | 中 | 高 | 当日修复 + 当日回归；超 3 个 P0 暂停 6 内测 |
| 客户数据泄露 | 低 | 致命 | 客户专属 namespace + K8s NetworkPolicy + 审计日志告警 |
| 客户对智能体结论不信任 | 中 | 中 | 解释"依据法规 + 案例 + 计算"的可追溯链路；提供人工复核入口 |
| 客户现场网络/设备限制 | 中 | 中 | 准备 4G/5G 备选 + 离线缓存模式 |
| 客户核心需求外溢出 | 中 | 中 | 限定范围，溢出需求进 backlog，明确不在 6 阶段内 |
| 公测客户相互干扰 | 低 | 中 | 限流 + 独立 tenant_id + 独立 DB schema |

## 6. 阶段出口

- 客户签字确认书 ×1（试点）；
- 公测报告 + 商业化建议；
- P0 / P1 全部清空或排期；
- 7 阶段启动条件（合规备案 / SLA 合同 / 运维就位）全部就绪。
