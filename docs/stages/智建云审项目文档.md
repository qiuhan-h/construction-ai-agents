# ① 项目介绍

## 1 智建云审项目介绍

### 1.1 学习目标

- 了解项目开发背景与痛点
- 了解智建云审系统实现过程

### 1.2 项目背景

智建云审（construction-ai-agents）是一个 **建筑工程 AI 智能体平台** ，旨在 **解决建筑施工过程中的安全审查、合规校验与现场监控的信息整合难题** 。传统建筑工程管理中，方案审查依赖人工逐条比对国家规范（GB 标准），合规校验需要跨专业（防火、抗震、节能、绿建）交叉核查，现场监控依赖人工巡检 + 事后告警，导致审查周期长、遗漏风险高、响应滞后。

本项目基于分布式 AI 架构，利用 **大语言模型**（LLM）、**MCP**（Model Context Protocol，模型上下文协议）和 **A2A**（Agent-to-Agent 协议）实现三大智能体协作：安全审核智能体（SafetyAuditAgent）、合规校验智能体（ComplianceAgent）、现场监控智能体（SiteMonitorAgent）。例如，用户提交一份施工方案，安全审核智能体自动解析文本、执行 LEC 风险评估、按 GB 50009 计算荷载组合，生成结构化审查报告并签章；现场监控智能体实时接入 IoT 传感器数据、BIM 模型与 GIS 电子围栏，自动研判告警并推送钉钉/企微通知。

### 1.3 项目目标及优势

**目标：**

构建一个基于 MCP 与 A2A 协议的 AI 建筑工程审查平台，覆盖安全审核、合规校验、现场监控三大场景，支持多租户 SaaS 模式，确保租户间数据隔离与配额限流，同时实现模块化设计，便于扩展。

**优势：**

- **MCP 和 A2A 协议的结合**：MCP 提供安全的模型与外部数据源/工具的链接（如 GB 规范检索、IFC 解析、GIS 空间计算），A2A 实现智能体间协作（如任务路由、异步执行、进度追踪），共同构建分布式架构，提高系统模块化、安全性和扩展性。
- **GB 标准结构化**：将 GB 50009（荷载）、GB 50016（防火）、GB 50011（抗震）、GB 50189（节能）、GB/T 50378（绿建）五本规范结构化为可检索知识库，支持语义检索与自动校验。
- **多租户 SaaS 架构**：RBAC + ABAC 双层权限控制，租户间数据隔离，配额限流（429 结构化错误），支持按用量计费。
- **实时 IoT/BIM/GIS 联动**：MQTT 接入传感器时序数据，InfluxDB 存储，BIM 模型进度同步，GIS 电子围栏空间告警。
- **移动端 + 内嵌应用**：响应式 Streamlit 移动端页面 + 钉钉 ISV / 企业微信内嵌应用免登，现场人员手机即可查看告警与日报。

### 1.4 项目使用示例

**示例一：施工方案安全审核**

用户提交施工方案文本，系统自动解析 → LEC 风险评估 → GB 50009 荷载组合计算 → 生成审查报告（Markdown + 结构化 JSON）→ HMAC-SHA256 签章 → 发布审查完成事件。

**示例二：设计文件合规校验**

用户上传设计图纸与说明文档，合规校验智能体依据四类 GB 标准自动核查（防火/抗震/节能/绿建），输出违规条目清单与整改建议，支持规范版本管理与变更追溯。

**示例三：现场告警与通知**

IoT 传感器数据超阈值 → 规则引擎研判 → 告警分发器推送钉钉群通知 + 短信 + 企微工作通知 → 日报生成器汇总当日施工情况 → 移动端可查。

## 2.1 LangChain 业务链与 LLM 注入

### 学习目标

- 熟悉 LangChain 业务链的编排方式
- 熟悉 LLM 注入器与降级策略

### 一、LangChain 业务链

项目在 [core/langchain/chains/](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/core/langchain/chains) 下定义三条业务链：

| 链 | 文件 | 作用 |
|---|---|---|
| SafetyChain | safety_chain.py | 安全审核链：方案文本 → LLM → 风险评估 + 整改建议 |

| MonitoringChain | monitoring_chain.py | 监控链：传感器数据 → LLM → 告警研判 + 日报摘要 |

每条链继承 LangChain 的 `RunnableSequential`，由提示词模板 → LLM 调用 → 输出解析器 三个阶段串联。

### 二、LLM 注入器

项目不绑定具体 LLM 框架，通过 [core/llm/injector.py](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/core/llm/injector.py) 的 `LLMInjector` 单例管理：

- 读取 `.env` 中 `LLM_PROVIDER`（mock / openai / anthropic / vllm）
- `mock` 模式使用 `FakeListLLM` 占位（不产生真实调用，开发期可用）
- `openai` 模式通过 httpx 直连 OpenAI 兼容接口（通义/DeepSeek/智谱/vLLM/Ollama）
- 缺少 `LLM_API_KEY` 时自动降级 mock 并打 warning 日志

### 三、业务工具适配

[core/langchain/tools/](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/core/langchain/tools) 下四个子模块将项目内部能力适配为 LangChain Tool：

| DocumentParseTool | document_parse.py | 文档/IFC 解析 |
| GISTool | gis_tools.py | 空间计算（围栏判断、热力图） |

## 2.2 MCP 协议

### 学习目标

- 熟悉 MCP 协议概念与工作原理
- 熟悉项目中 MCP 的三类能力注册

### 一、什么是 MCP

**MCP**（Model Context Protocol，模型上下文协议）由 Anthropic 开源，用于 **模型与外部数据源/工具的标准化连接** 。MCP 定义了三类能力：

- **Resources**（资源）：只读数据源（如 GB 规范文本、项目文档）
- **Tools**（工具）：可执行函数（如荷载计算、IFC 解析、空间计算）
- **Prompts**（提示词）：预置提示模板（如安全审查提示词、合规校验提示词）

### 二、项目中的 MCP 实现

项目的 MCP 实现位于 [core/mcp/](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/core/mcp)，核心组件：

- **MCPServer**（server.py）：MCP 服务注册中心，管理 resources / tools / prompts 三类注册表
- **MCPHandlers**（handlers.py）：各智能体的 MCP 处理器（如安全审核的 `read_regulation`、合规校验的 `read_standard`）
- **REST 路由**（api/routers/mcp_router.py）：暴露 `/api/v1/mcp/resources`、`/api/v1/mcp/tools` 等端点

MCP 资源 URI 采用最长前缀匹配（如 `gb://50009/*` 匹配所有荷载规范相关资源）。

## 本节小结

本部分介绍了 MCP 协议的三类能力（Resources/Tools/Prompts）与项目中的 MCP 注册中心实现。

## 2.3 Agent 智能体

### 学习目标

- 熟悉 Agent 概念与项目中三个智能体的职责
- 熟悉智能体的事件驱动协作方式

### 一、什么是 Agent

Agent（智能体）是能够 **感知环境、自主决策、执行行动** 的 AI 实体。在本项目中，每个 Agent 对应一个建筑工程专业领域，具备：

- **AgentCard**：自我描述清单（名称、版本、技能列表、端点地址）
- **Skills**：可被外部调用的能力（如 `plan_review`、`fire_check`、`alert_judge`）
- **事件订阅**：通过 EventBus 订阅领域事件，实现智能体间松耦合协作

### 二、三大智能体

| 智能体 | 类名 | 职责 | 技能 |
|---|---|---|---|
| 安全审核 | [SafetyAuditAgent](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/agents/safety_audit_agent/agent.py) | 施工方案/图纸/规范审查 | `plan_review`（方案审查）、`load_combination`（荷载组合） |
| 合规校验 | [ComplianceAgent](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/agents/compliance_agent/agent.py) | 设计文件合规校验 | `fire_check`、`seismic_check`、`energy_check`、`green_check` |
| 现场监控 | [SiteMonitorAgent](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/agents/site_monitor_agent/agent.py) | 施工现场 IoT/BIM/GIS 监控 | `alert_judge`（告警研判）、`daily_report`（日报）、`bim_progress_sync`（BIM 进度同步） |

### 三、事件驱动协作

智能体间通过 `core/events/event_bus.py` 的 EventBus 实现松耦合：

- 安全审核发现 CRITICAL 风险 → 发布 `alert.triggered` → 现场监控订阅并推送通知
- 合规校验完成 → 发布 `inspection.completed` → 编排器记录时间线
- 现场监控告警 → 发布 `alert.triggered` → 安全审核可订阅补充审查

## 本节小结

本部分介绍了 Agent 概念、三大智能体的职责与技能、事件驱动的协作方式。

## 2.4 A2A 协议

### 学习目标

- 熟悉 A2A 协议概念与工作原理
- 熟悉项目中 A2A 的 JSON-RPC 帧结构与端点

### 一、什么是 A2A

**A2A**（Agent-to-Agent）是智能体间通信协议，与 Google A2A 思路对齐。核心能力：

- **Agent 发现**：`agent.discover` 查询可用智能体清单与 AgentCard
- **消息发送**：`agent.send_message` 向指定智能体发送任务（同步或异步）
- **任务管理**：`agent.get_task` / `agent.cancel_task` / `agent.list_tasks` 查询与控制任务

### 二、项目中的 A2A 实现

A2A 协议定义位于 [core/a2a/protocol.py](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/core/a2a/protocol.py)，采用 **JSON-RPC 2.0 风格帧**：

```
请求帧: { "jsonrpc": "2.0", "id": "xxx", "method": "agent.send_message", "params": {...} }
响应帧: { "jsonrpc": "2.0", "id": "xxx", "result": {...} }
错误帧: { "jsonrpc": "2.0", "id": "xxx", "error": { "code": 50001, "message": "..." } }
```

核心组件：

- **A2AServer**（core/a2a/server.py）：A2A 服务端，处理 JSON-RPC 请求，管理任务状态机（submitted → working → completed/failed），支持 `state` + `timestamp` 防重放
- **A2AMessage**（core/a2a/message.py）：消息帧结构（parts 可携带 text / file / data 三种类型）
- **AgentCard**（core/a2a/agent_card.py）：智能体自描述清单
- **REST 路由**（api/routers/a2a_router.py）：暴露 `/api/v1/a2a/agents` 发现端点，全部加 `Depends(get_auth_context)` 鉴权

## 本节小结

本部分介绍了 A2A 协议的 JSON-RPC 帧结构、服务端任务状态机与 REST 端点。

## 2.5 多租户 SaaS 与 ABAC

### 学习目标

- 熟悉多租户 SaaS 架构与配额限流
- 熟悉 RBAC + ABAC 双层权限控制

### 一、多租户架构

项目支持多租户 SaaS 模式，核心组件位于 `services/` 与 `models/domain/`：

- **TenantService**（services/tenant_service.py）：租户注册、试用套餐（free/pro/enterprise）、初始配额
- **QuotaService**（services/quota_service.py）：配额计数（Redis 原子操作），超额返回 429 + 结构化错误体
- **BillingService**（services/billing_service.py）：按用量计费（UsageRecord 记录）

### 二、RBAC + ABAC 双层权限

- **RBAC**（角色控制）：请求先过 RBAC 鉴权，**RBAC 拒绝直接 403，跳过 ABAC**
- **ABAC**（属性控制）：RBAC 通过后进入 [ABACEngine](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/core/security/abac_engine.py)，基于时间窗、敏感度、租户隔离属性做细粒度判断
- **FieldMasker**：ABAC 拒绝敏感字段时脱敏返回（如 `***` 替换），而非整体拒绝
- **TenantMiddleware**：通过中间件注入租户上下文，后续所有数据库查询自动带 `tenant_id` 过滤

## 本节小结

本部分介绍了多租户 SaaS 架构、配额限流、RBAC + ABAC 双层权限与字段脱敏。

## 3.1 项目架构与代码架构图

### 学习目标

- 熟悉项目业务架构图
- 熟悉项目代码架构图

### 一、项目架构图

智建云审是基于 **A2A** 与 **MCP** 协议实现的多 Agent 协作系统。用户通过 Streamlit 前端（7 个页面）或移动端（钉钉/企微内嵌）输入请求，系统由 API 层（FastAPI）作为统一入口，通过编排器（Orchestrator）调度三大智能体：

| 智能体 | 目录 | 功能 |
|---|---|---|
| 安全审核智能体 | `agents/safety_audit_agent/` | 方案审查、LEC 风险评估、GB 50009 荷载组合、报告签章 |

| 现场监控智能体 | `agents/site_monitor_agent/` | IoT 传感器接入、BIM 进度同步、GIS 电子围栏、告警分发 |

每个智能体背后由 MCP 工具服务器提供数据访问能力（GB 规范检索、IFC 解析、空间计算、向量检索），MCP 服务器直接与 PostgreSQL / InfluxDB / ChromaDB 交互。IoT 数据通过 MQTT 接入，BIM 数据通过 Autodesk APS 接口获取。

class MCPServer:
    """MCP 服务注册中心：管理 resources / tools / prompts 三类注册表。"""

    def register_resource(self, uri: str, handler): ...
    def register_tool(self, name: str, handler, schema: dict): ...

## 3.4 实现 A2A Server

### 学习目标

- 熟悉 A2A Server 的任务状态机
- 熟悉 A2A 消息帧结构与防重放

### 一、A2A Server 核心

[core/a2a/server.py](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/core/a2a/server.py) 实现 A2A 协议服务端：

- **任务状态机**：`submitted → working → input_required → completed / failed / canceled`
- **并发安全**：任务状态转换加锁（`with self._lock`），防止锁外并发
- **防重放**：消息携带 `state` + `timestamp`，过期或重复消息拒绝

### 二、消息帧结构

```python
# core/a2a/message.py
class A2AMessage:
    message_id: str          # 全局唯一 ID
    timestamp: str          # ISO 时间戳（防重放）
    sender: str             # 发送方 agent name
    target: str             # 目标 agent name
    parts: list[MessagePart]  # 消息内容（text / file / data）
    task: Task | None       # 关联任务

class MessagePart:
    kind: str               # "text" / "file" / "data"
    content: str            # 文本内容 / 文件路径 / JSON 字符串
```

### 三、REST 端点

[api/routers/a2a_router.py](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/api/routers/a2a_router.py)：

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/v1/a2a/agents` | GET | 列出所有已注册智能体（AgentCard） |
| `/api/v1/a2a/agents/{name}` | GET | 获取指定智能体的 AgentCard |
| `/api/v1/a2a/messages` | POST | 向指定智能体发送 A2A 消息 |

所有端点均加 `Depends(get_auth_context)` 鉴权，防止未授权调用。

- 进度偏差检测：`ProgressTracker` 比对计划 vs 实际，输出 `delayed` / `ahead` / `on_track` 状态

### 二、边缘端 Dockerfile

[deployment/docker/Dockerfile.edge](file:///d:/Trae/woek解压盘/workspace-full/zhijian2/智建2/construction-ai-agents/deployment/docker/Dockerfile.edge)：

- **多阶段构建**：builder 阶段安装依赖，runner 阶段仅复制运行时
- **EDGE_MODE 环境变量**：边缘端模式，单 worker、本地缓存
- **非 root 用户**：容器以 `appuser` 运行
- **healthcheck**：内置健康检查端点
- 适用于工地现场边缘设备（如树莓派/工控机）

## 附录：一些小技巧

### Windows 查询并杀掉占用端口的进程

```Plain Text
# 查找占用 8000 端口的 PID
netstat -ano | findstr :8000

# 杀掉进程
taskkill /F /PID 12345
```

### PowerShell 一键杀掉 8000 端口

```PowerShell
netstat -ano | findstr :8000 | ForEach-Object { $_.Split(' ',[System.StringSplitOptions]::RemoveEmptyEntries)[-1] } | Select-Object -Unique | ForEach-Object { taskkill /F /PID $_ }
```

### 验证端口是否释放

```Plain Text
netstat -ano | findstr :8000
# 没有输出代表端口已释放
```
