================================================================================
core/rules/ 目录代码生成提示词合集
================================================================================
本文件汇总 core/rules/ 目录下所有代码文件的"代码生成提示词"。
每一段都是一段独立的 prompt，可直接复制粘贴给大模型，让其生成对应代码文件。
分段处理，每段对应一个代码文件。生成代码时请严格遵守每段中的接口契约和约束。

================================================================================

【约束】

【生成文件 2】operator.py
================================================================================
你是一名 Python 后端开发者。请实现 operator.py。

【背景】
规则运算符工具：实际值 vs 阈值。

【依赖】
- from __future__ import annotations
- from typing import Any

【必须实现的函数】
1. compare(actual: Any, operator: str, threshold: Any) -> bool  # 实际值与阈值按 operator 比较。 支持的 operator：<, <=, >, >=, ==, != 数值：直接比较 字符串：== / != 按字面比较，其它按字符串"长度"或字典序（与 dict 一致） None：== None 仅当 threshold == None；其它 operator 一律 False
2. _coerce(v: Any) -> Any  # 尽量转 float；不能转就保留原值。

【约束】
- 严格遵循上述接口签名（参数名、类型注解、返回值类型）
- 保持向后兼容，不修改已有公共接口
- 新增功能须补充对应单元测试

【输出】
完整的代码文件，使用中文 docstring 和类型注解，并在关键逻辑处添加中文行内注释。

【生成文件 3】rule.py
================================================================================
你是一名 Python 后端开发者。请实现 rule.py。

【背景】
规则数据类与运算符工具（4a 合规 / 4b 告警 共用）。 公共基类 BaseRule + compare 工具是 4a ComplianceRule 与 4b AlertRule 共享的； 4a / 4b 各自继承 BaseRule 增加业务字段。

【依赖】
- from __future__ import annotations
- from dataclasses import dataclass
- from typing import Any

【必须实现的类】

   方法：
   - __post_init__(self) -> None
1. class ComplianceRule(BaseRule)：4a 合规规则：在 design_doc[field] 上比较值。
1. class AlertRule(BaseRule)：4b 告警规则：在 metric 上比较值。

【约束】
- 严格遵循上述接口签名（参数名、类型注解、返回值类型）
- 保持向后兼容，不修改已有公共接口
- 新增功能须补充对应单元测试

【输出】
完整的代码文件，使用中文 docstring 和类型注解，并在关键逻辑处添加中文行内注释。

================================================================================
目录级生成约束
================================================================================
1. 所有文件必须使用中文 docstring 和类型注解（from __future__ import annotations）
2. 严格遵循各文件【必须实现的类/函数】中定义的接口签名
3. 新增功能须补充对应单元测试，运行 pytest 确认无回归
4. 涉及环境变量的配置须同步更新 .env.example 与 config/settings.py

【中文注释规范】（所有生成的代码必须遵守）
- 模块顶部 docstring：中文说明文件职责、设计原则
- 类 docstring：中文说明类用途、关键属性
- 方法/函数 docstring：中文说明功能、参数含义、返回值
- 关键代码逻辑：必须添加中文行内注释（# 注释），解释"为什么这样做"
- 复杂分支、循环、异常处理：必须有中文注释说明意图
- 禁止使用英文注释；禁止无注释的复杂逻辑块
- 常量、枚举、配置项：必须有中文注释说明用途
